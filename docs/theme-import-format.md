# 主线成员导入格式

系统**不判断**"当前市场在炒什么"，也**不判断**"某只票属不属于某条主线"——
这两件事需要新闻面/情绪面语料，本地一概没有。主线清单由你给定，成员归属由
你本地的外部判定器（kimi code + swarm）产出后导入。

系统只负责一件事：把你给的主线**按强弱排出顺序**，并把排名结果作为买点确认的一层。

## 导入

```bash
zt theme import themes.json --replace
```

- `--replace`：先清空本次涉及的每条主线的旧成员再写入。**外部判定器整体重跑时必须带上**，
  否则已经退出主线的票会残留在库里。
- `--source`：判定来源标记，默认 `kimi-swarm`，写入 `theme_members.source`，
  便于日后区分人工标注与模型标注。

## JSON 格式

顶层是数组，或 `{"records": [...]}` 包一层：

```json
[
  {
    "theme": "商业航天",
    "ts_code": "600879.SH",
    "confidence": 0.9,
    "reason": "卫星载荷与测控设备，主营直接受益于低轨星座招标"
  },
  {
    "theme": "商业航天",
    "ts_code": "002151.SZ",
    "confidence": 0.75,
    "reason": "北斗导航芯片，产业链关联但非核心"
  }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `theme` | 是 | 主线名称。库里没有会自动建档 |
| `ts_code` | 是 | 股票代码，大小写不敏感（自动转大写） |
| `confidence` | 否 | 归属置信度 0~1，默认 1.0。越界会被夹住而不是丢弃 |
| `reason` | 否 | 判定理由，原样保存，供复盘时回看当时为什么这么归类 |

缺 `theme` 或 `ts_code` 的记录会被跳过并在导入结果里列出，不会静默吞掉。

## 强弱怎么排

对每条主线的成员集合，在最近 N 个交易日窗口（默认 5）内算两路信号，
**两路都只用本地已有数据，零 API 成本**：

- **行情面**——组内累计涨幅中位数。中位数抗极端值，一两只妖股拉不动整条主线的读数。
- **情绪面**——组内涨停次数（权重 2）+ 放量攻击次数（权重 1，量比>3 且涨>2%）。

两路各自映射成"强于百分之多少的行业"，等权合成 0~100 的强度，50 分 = 与中位数行业一样强。

几个必须知道的细节：

- **为什么用百分位而不是绝对分**：最初的绝对分公式在普涨周直接饱和——
  实测 20260807 排名前 12 的行业强度全是 100.00，完全分不出强弱。
- **情绪面做了经验贝叶斯收缩**：涨停是稀有事件，6 只票 × 5 天只有 30 个样本，
  期望涨停数不足 1，拿到 0 是最可能的结果而不是"这条主线弱"。不收缩会系统性地
  把小主线打到地板。
- **成员少于 3 只的主线不参与排名**（统计不可信），但会在 `zt theme rank`
  和每日流水线的 warnings 里明确报出来，不会静默消失。
- **涨停口径来自 `daily_kline.is_limit_up`**，不是 Tushare 的涨停板接口——
  `limit_list_d` 和 `top_list`（龙虎榜）在当前账号下都返回"没有接口访问权限"。
  龙虎榜没有替代数据，用"放量攻击次数"当资金关注度代理。

## 没导入主线会怎样

买点确认的主线层退回 `stock_basic.industry` 行业分类兜底，
权重减半（行业不是"炒作主线"，只是所在板块的冷热），
且结果里 `kind` 字段会如实标成 `industry`。每日流水线会在 warnings 里提示。

## 查看

```bash
zt theme list                    # 主线清单与成员数
zt theme members 商业航天         # 某条主线的成员
zt theme rank --lookback 5       # 强弱排行（含行业参照系）
zt theme deactivate 商业航天      # 退潮了：保留历史，不再参与排名
```
